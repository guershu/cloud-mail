# 账户管理

管理员登录后从侧栏「账户管理」进入 `/accounts`。

快速创建使用姓名式前缀（例如 `lin.chen`），发生冲突时添加 2–3 位数字；可自定义前缀。每次创建同时写入用户、收信地址和保险库，D1 batch 保证原子提交。账户默认「临时」，立即持久化；保存可添加备注。支持密码查看/复制、回收站与恢复。

## 部署

1. 在 Worker Secret 中设置独立的 `ACCOUNT_VAULT_KEY`，使用密码管理器生成并保管至少 32 位随机值。不要复用 JWT 密钥。此密钥直接用于现有密码解密，不能随意替换；轮换需要先迁移密文。
2. 保留原有 db、kv、admin、domain、jwt_secret 等配置，发布修改后的 Worker 和前端。
3. 第一次访问管理接口自动创建 managed_account 表，不重建现有表。
4. 管理员打开 `/accounts`，创建测试账户，用独立浏览器验证其登录，并从外部邮箱发送邮件验证预览。

## 权限与数据

所有 managed 接口仅允许 env.admin 对应的登录用户访问。密码 AES-GCM 加密保存，使用邮箱地址作为附加认证数据；明文仅按需返回，响应不缓存。用户登录密码沿用原项目的哈希方案。邮件正文经 DOMPurify 清理并在 sandbox iframe 中展示，默认禁止外部图片及脚本。

删除为软删除，撤销现有登录并拒收来信，邮件保留；恢复重新启用。第一版不提供永久删除或自动过期。请通过此页面管理这些账户；原有用户后台改密不会同步保险库中的密码。

预览每 10 秒刷新当前账户最新 50 封邮件，可加载更早邮件；浏览器隐藏时暂停。当前只保存邮箱密码与用途备注，不含第三方网站独立凭据字段。

## 本地检查

`node --test tests/managed.test.mjs` 使用 SQLite 验证创建、密码密文解密、邮件归属、软删除恢复、重名及管理员限制。密码哈希与角色查询使用测试替身，不替代线上端到端验证。

前端：在 mail-vue 下执行 `pnpm install --frozen-lockfile && pnpm run build`。
